# Web3D Agent CLI 架构

CLI 是独立实现，使用兼容 OpenAI 的 Chat Completions 协议。没有依赖 Claude Code、Claude Agent SDK 或第三方代理框架；参考的是模型与工具交替执行的通用结构。

```text
cli.ts
  ├─ config.ts             配置优先级与参数校验
  ├─ rules/index.ts        内置规则 + 项目规则 → system prompt
  ├─ session.ts            用户轮次与配对工具消息的本地存储
  └─ agent.ts              单次用户任务的执行循环
       ├─ providers/openai.ts  fetch + JSON / SSE → 完整 assistant 消息
       ├─ 审批与模式检查
       └─ tools/index.ts
            └─ tools/workspace.ts  路径、文本、读取证据与写入
```

## 一次任务如何执行

1. 记录用户消息并保存会话。
2. 在上下文预算内选取完整用户轮次，加入当前项目规则。
3. 请求模型，文本可以实时显示；工具调用必须等完整响应校验通过后才执行。
4. 对每个工具调用解析 JSON 参数，检查当前模式和审批。
5. 工具执行后，无论成功、拒绝还是出错，都生成关联 `tool_call_id` 的结果。
6. 保存配对后的消息，进入下一次模型调用，直到模型不再提出工具调用。
7. 取消、接口错误、输出截断、上下文或轮次预算达到边界时，明确结束当前任务。

V1 工具顺序执行，优先保证编辑顺序与文件状态一致。没有把所有只读调用直接并发，也没有在流尚未完整结束时启动工具，因此不会因中途断流执行半截参数。

## 规则与权限

领域规则描述质量要求：Three.js 资源所有权、动画、相机与性能，以及 Python API 契约、异步边界、持久化与验证。规则不会自动把项目改造成特定框架。

运行时权限独立于自然语言规则。修改与命令分别决策；`plan` 拒绝任何写入与命令。文件工具拒绝常见私密路径与工作区外访问。命令工具需要单独授权，批准后没有操作系统层面的隔离。

## 状态与恢复

会话位于目标项目的 `.web3d-agent/sessions/<UUID>.json`。每次保存使用临时文件和替换，恢复时验证版本、工作目录及工具调用配对。配置与 API 密钥不会作为会话元数据保存；用户主动输入或命令输出中的敏感内容仍属于会话正文。

文件读取证据仅驻留当前进程。较大文件按完整行分页，最终序列化大小也计入输出预算；同一版本的全部行都被返回后才获得完整读取状态。覆盖前验证当前内容与读取版本的 SHA-256 一致；恢复历史不恢复读取授权。写入保护减少覆盖较新修改的风险，但不提供跨进程锁或完整事务。文件符号链接明确拒绝编辑，避免把重命名写入误用于替换链接本身。

当前版本根据字符数约束请求，移出旧轮次时通知模型和用户；本地历史仍保留。当前轮次超出预算会停止，不假造摘要，不拆散工具调用与结果。

## 验证分层

- Provider 测试使用本机 HTTP 服务，检查实际请求映射、SSE 分片与错误边界。
- 工具测试使用临时目录，检查路径、过期写入、文字替换、进程超时和取消。
- Agent 测试使用可控模型响应，检查审批、结果配对和循环停止。
- CLI 测试启动真实 Node 子进程，贯通初始化、离线工具执行与会话恢复。

离线演示只模拟模型决策，目录检查等工具真实执行。它不证明某个商业模型或网关可以连通。`check_project` 的启发式观察也不等同于 Python 测试、前端构建或 Three.js 实际渲染结果。
